# JH Diesel Desktop — v0.3 development source

This update adds your logo, an experimental isolated Windows RP1210 worker, CSV graphs, checkbox tune proposals and a sourced protocol/controller roadmap. This is source plus a built desktop renderer, not an installer or a working universal ECU programmer.

## Try the software

Requirements: supported Node.js (24 recommended), npm, and Windows 10/11 for adapter use. For native work, install Python 3.10+ and the official NEXIQ driver. Python architecture must match the vendor DLL (often x86 for an RP1210 32-bit driver). `JH_PYTHON` may point to a trusted absolute Python executable path. No vendor drivers, SDKs or Python/Electron runtimes are bundled in the ZIP.

1. Extract this folder and install dependencies: `npm ci`.
2. Build the standalone renderer: `npm run desktop:build`.
3. Open the built desktop UI: `npm run desktop:built`.
4. In Vehicle connection, use **Discover Windows drivers**, select a registered device and an advertised capture protocol, then **Open adapter client**. A successful adapter client is not vehicle identification. **Capture batch** collects a bounded raw batch; **Export capture** saves it. Disconnect when finished.
5. In **Logs & graphs**, import numeric CSV or load the explicitly synthetic demo. Choose channels and a time window; export the visible window. No vehicle samples are generated by the demo.
6. In **Tune planner**, choose review items, read explanations and describe your goal. Save the draft on the device or export JSON. No ROM changes are produced.

The native worker is a development child process, not an installed/signed Windows service. Use only locally controlled renderer code. No arbitrary native command or vendor DLL path is accepted from the renderer. Packaging/signing and further hardening remain work before distribution.

For browser development, `npm run dev` serves the existing web app. Native discovery is available only through the Electron preload. For desktop renderer production assets, use the separate `desktop:build` command; the existing web build produces Vercel assets and is not the Electron renderer.

## Verification

Passed: `npm run typecheck`, `npm run build`, `npm run desktop:build`, four CSV parser tests, four Python worker/discovery tests, native Python compile and Electron JavaScript syntax checks.

Browser visual/interaction verification was attempted but blocked by this environment: the installed Chromium cannot create its process socket, and the alternate browser runtime fails to start. Consequently desktop/mobile appearance, graph interactions and Electron execution have not been visually verified. Windows driver loading, adapter connection and vehicle communication remain untested. Do not interpret passing software tests as hardware support.

Tests: `npm run test:jh` and `python -m unittest discover -s desktop/native-service/python -p "test_*.py"`.
